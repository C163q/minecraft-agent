# 玩家动作事件的实施与验证

当前状态：已完成四项。61 项 Rust 测试、Java 队列测试与 26.3 独立实例完整回归通过。安装包已与测试构建核对。

按[设计规格](../specs/2026-11-27-player-action-events.md)在 26.3 本地单人实例实施。使用 subagent-driven-development 将原版服务端采样、监听命中记录和独立实机用例分别验证。

1. [x] **服务端动作。** 核对 26.3 字节码，在成功移除方块、服务端接受方块交互、物品挡下正数伤害时，传给客户端已固定的现场数据。用实际输入区分最终成功、放行、拒绝及双手回退。
2. [x] **队列与停止帧。** 在 `InputQueue.observe` 收集被接纳的监听，在 `Playback` 的当前请求保留最近 32 条，终止帧读回前封存。用队列测试验证注册顺序、重复通知、旧监听和容量，再验证桥接中 JSON 空值。
3. [x] **客户端、MCP 与参考。** 观察本地玩家接地边沿和实际进入的界面；Rust 解析器识别五个名字，握手拒绝旧 Mod，返回函数透传报告并支持关闭图片。运行 Rust 测试、格式及 Clippy，同步事件文档。
4. [x] **实机与交付。** 独立存档通过正式 MCP 对照客户端、服务器和停止帧，验证挖掘、开关门、锄地、去皮、开箱、界面、离地和格挡。复核提前返回、超时与跨暂停记录，构建并核对安装产物，合并到 main。

实机对照使用[动作事件用例](../../../tests/game/action_events.py)。暂停期间持续右键的回归在旧构建观察到服务端收到 4 次目标格使用请求。修复后，八个暂停客户端 tick 后仅收到一次，恢复首拍释放右键后仍为一次。
