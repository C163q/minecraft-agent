# 输入函数的实施与验证

三项工作均已完成。36 项 Rust 测试、Java 队列与移动测试，以及 Minecraft 26.3、Fabric Loader 0.20.1 独立实例的完整回归通过。安装的 Mod 和 MCP 与构建产物哈希一致。

目标与时序以[函数规格](../specs/2026-11-27-input-functions-design.md)为准。Rust 保留局部符号表和源行，Java 25 在 Minecraft 26.3 的游戏线程按需执行调用。深度上限为 32，两输入拍之间每份提交最多进入函数 4096 次。

1. **解析与传输**。在 `src/parser.rs`、`src/keyboard.rs` 和 MCP 编码器中支持完整定义检查及前向引用。wire 新能力为 `input_functions`，提交含 `functions`（函数名到 runs 数组），零拍 run 用 `call`（不含美元前缀的名字）或 `return: true`。用 `cargo test --offline` 检查旧 Mod、未调用函数内错误、递归和真实源行。
2. **游戏队列**。从 `tests/queue/InputQueueTest.java` 建立失败用例，在 `InputQueue.java` 维护调用现场、监听归属和已触发分支。检查双层同拍监听、显式与自然返回、跨维度死亡、前台块更换以及 32/33、4096/4097 边界。超限时队列撤销所属提交并抛出带来源的 `InputQueue.FunctionLimit`。`Playback` 负责暂停并通过已确认停止边界完成错误响应。
3. **实机与交付**。在 `tests/game/` 使用正式 MCP 提交函数脚本并读取停止图与队列。覆盖受伤、正常超时、监听退出、暂停时提交同名函数、运行错误后的恢复。更新脚本索引、查询和开发资料，运行完整 Rust、Java、实机回归，审阅分支并安装验证后的产物。

## 验证结果

同一份等待脚本在正常超时和服务端确认受伤后都返回调用者，后者提前执行下一拍。处理块调用的辅助函数在暂停后可返回到原处理块。返回给 MCP 的停止帧与显式保存的 PNG 字节一致。跨维度重生后，死亡处理块使用原函数表执行辅助调用，旧世界的入口余项被清理。

独立审阅和回归复核了三个边界。函数末行暂停时，即便队列条目为零仍可查到等待返回的调用栈。截图写入失败与函数超限落在同一边界时，错误响应保留两项诊断。旧事件处理块清除当前请求后，若随即返回就能当场结束，若后面还有一拍按键则先派发再停止。Java 测试也覆盖跨维清理后只剩死亡处理块时的请求归属。用例见[函数实机回归](../../../tests/game/functions.py)与[队列测试](../../../tests/queue/InputQueueTest.java)。
