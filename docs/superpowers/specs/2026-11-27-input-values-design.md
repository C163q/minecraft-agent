# 输入脚本的变量、表达式与返回值

本规格描述拟加入 Minecraft 26.3 输入脚本的语言能力。目标是让脚本读取一次事件的数据，调用可复用的函数，根据运行时的值构造键鼠输入，并把结果交给模型。示例用于实施与验收。

```text
FUNCTION $wait_for_break($ticks)
BEGIN
    ON(BlockBroken($event))
    BEGIN
        RETURN $event.id
    END
    Wait($ticks)
    RETURN null
END
BEGIN
    MousePress(left)
    LET $broken = $wait_for_break(40)
    MouseRelease(left)
    Print("broken={}", $broken)
    RETURN $broken
END
```

监听命中时，函数返回原方块 ID；等满四十拍则返回 null。两条路径都先松开左键，然后打印并返回结果。函数调用和返回的既有边界见[函数语义](../../input-script/functions.md)。

## 值与名字

变量保存 JSON 值，包括 null、布尔值、数字、字符串、数组、对象。对象字段名可以写成标识符或双引号字符串。数组和对象的元素可由表达式产生。未闭合的对象与数组内部允许换行、空行和行注释，整个声明或赋值消耗零拍。字符串中的 `//` 是字符串内容。

```text
LET $target = {
    id: 1,
    pos: [1.0, 2.0, 3.0],
    "block-id": "minecraft:stone"
}
LET $copy = $target
SET $copy.pos[0] = 2.0
```

变量赋值、参数绑定、函数返回均采用值语义。更改示例里的副本只影响副本。每条 `SET` 有一个赋值目标。对象末级字段可创建或覆盖；写入数组元素要求父数组存在、下标为有效的从零起算整数。路径无效时原值保持完整。读取对象缺失字段得到 null，对 null 继续读取字段仍得到 null。对数字等其他类型读取字段，或数组下标越界，产生错误。未声明的变量名属于提交错误。

每次独立提交、函数调用和事件处理都有自己的作用域。形参在函数体所在作用域声明。普通函数通过显式参数接收值，导入库、递归和不同提交中的同名调用各自保持绑定。每次触发的处理块可以读写注册位置可见的变量，取执行到该表达式时的当前值。新提交不能访问旧提交里的名字。旧块及其中的调用在暂停后继续使用原值。

同一作用域重复声明名字报错，允许在内层遮蔽外层。`LET $key = $key` 的右侧先在声明之前的词法环境中解析，左侧在右侧成功完成后生效。`SET` 写最近可见的声明。所有事件继续支持 `ON(Hurt)` 等原写法，也接受一个自选名字，如 `ON(Hurt($hit))`。这个名字属于处理块，可以遮蔽外层同名绑定；绑定及其成员只读。每次命中绑定一次观察时的事件快照，包括 `event` 和该事件已有的[现场字段](../../input-script/events.md#动作事件)。处理块中途暂停不会改变快照。处理块按现有生命周期清理；顶层自然结束后仍可续跑的处理块保留其所需的词法环境。

## 表达式与游戏输入

四则运算、一元负号和括号使用常规数值优先级。相同优先级的二元运算从左到右求值。字符串、布尔值和 null 不隐式转为数值。整数加减乘以及可整除的整数除法须保持精确，覆盖现有 `Wait` 的完整无符号 64 位时长。`5 / 2` 得 2.5；除零报错。

| 纯计算函数 | 返回值 |
| --- | --- |
| `Floor(x)`、`Ceil(x)` | 分别向下、向上取整；整数入参保留精确值 |
| `Abs(x)` | 绝对值 |
| `Min(a, b)`、`Max(a, b)` | 两个数中的较小值、较大值 |

纯函数可嵌套于表达式，包括指令参数、用户函数实参、赋值和 `RETURN`。`Wait(Floor(5 / 2))` 等两拍，`Wait(5 / 2)` 和 `Wait(Floor(0.8))` 不满足正整数条件。动态等待开始时确定时长；暂停前走过的拍和保留的余量沿用[计拍规则](../../input-script/timing.md)。鼠标数值表达式放在现有单位里，如 `MouseMove(Rotate(-Abs($yaw)), Px(0))`。

`Key(w)`、`Mouse(right)` 等原有字面量写法继续有效。键盘和鼠标按钮指令均接受求值为对应名称字符串的参数，例如 `Key($key)`、`MouseRelease($button)`。`"1"` 可以表示数字键，数字 1 在这里是类型错误。键名及按钮名继续由现有对照表和游戏版本决定。候选输入拍的动态参数全部求值并校验后才合并、派发；同块中解析到同一键的按下与释放仍冲突，跨块按原有覆盖规则处理。

## 函数、返回与暂停

`FUNCTION $name($a, $b)` 声明位置参数，按值传递，调用的参数个数须严格匹配。保留无参定义 `FUNCTION $name` 和调用 `$name()`。自定义函数可以单独调用，或作为 `LET`、`SET` 的整个右侧。它可以跨拍、触发事件或暂停，因而在输入行开始前必须通过独立语句取得其结果。待返回的赋值在续跑时继续同一次调用；每个实参只在调用开始时计算一次。

函数内 `RETURN 表达式` 把值交给调用者；自然结束或裸 `RETURN` 得到 null。监听里的 `RETURN` 返回注册监听的那一次调用，按原有规则退出其活动子调用；处理块调用的辅助函数仍返回给处理块。多监听沿用注册顺序。若同拍前面的返回撤销了后面的处理块，后者还未执行的写入或打印也一并撤销。

当前提交的顶层显式返回值时，停止结果附 `return_value`，显式返回 null 也保留该字段。顶层自然结束、裸 `RETURN` 或尚在等待时的普通暂停均省略该字段。旧提交在新请求期间返回，其值只归旧提交。已有的 `PAUSE`、`max_ticks`、`CLEAR`、F8 及存档切换沿用各自的输入清理与保留规则。

## 打印及错误反馈

`Print("$var: {}, $ret: {}", $var, $ret)` 独占一行，消耗零拍。格式为字符串字面量，`{}` 按顺序替换，`{{`、`}}` 输出字面花括号，字符串中的美元符号保留。提交时验证格式和实参数量。字符串按原文打印，其他值按紧凑 JSON 输出。所有实参求值成功才追加整行及一个换行符。

`stdout` 是当前工具调用期间实际执行的打印文本，按顺序收集所有提交及其监听和函数的输出；空输出省略。在暂停、正常停止、运行时错误与触发存档切换时均交付已经生成的内容。新请求只收集续跑后的新输出。F8 单独运行时没有接收打印结果的请求。`include_screenshot` 只控制工具返回的图片。

Rust 在提交前解析、绑定和校验，包括库及未调用函数。可静态识别的错误保留原游戏状态。运行时由 Mod 在现有输入队列、函数调用和事件处理块的位置上求值。单在 MCP 展开脚本无法处理暂停后的 F8、事件快照或尚未返回的函数。

运行时错误终止出错的整份提交（含函数、监听与待执行操作），在当前边界暂停其他提交。动态输入行失败时不派发该拍的任何游戏输入，其他提交仍可在恢复后执行该拍。此前成功的零拍指令、已派发拍、显式保持状态及已启动的移动按既有规则保留。当前工具调用返回错误、`pause_reason: "error"`、已执行 `ticks`、责任块及源位置、调用栈和具体原因，沿用停止帧及可选返图规则。没有活动请求时，手动恢复遇错仍能通过 `inspect_input` 诊断。

## 建议采用的三个求值边界

1. **可暂停赋值的目标。** 对 `SET $items[$i] = $f()`，建议在调用前按值记住下标并验证目标能写，再执行函数。返回时在当前的 `$items` 上检查并写入同一条路径。如果监听仅把 `$i` 从 0 改成 1，仍写第 0 项；如果监听已经清空数组，写入时报错。写回只更新目标元素，保留函数执行期间对其他元素的修改。
2. **首个等待拍。** 建议动态 `Wait($n)` 在首次实际消费等待拍前，随整拍输入一起求值。若较新的监听先在该边界 `PAUSE`，旧块的等待尚未消费，恢复后取最新值。第一拍成功消费后，只维护剩余拍数。对于 `Wait($n) Key($key)`，键名在等待结束后的按键拍才取值。
3. **提前校验的范围。** 建议在提交时检查纯字面量表达式以及只含常量的子表达式。例如 `Wait(5 / 2)` 不满足整数约束，`Key("unknown_key")` 不能解析为物理键，均在恢复游戏前拒绝。引用变量的类型和值在执行该指令时校验，即使附近曾写 `LET $n = 0`；静态检查仍覆盖名字、只读绑定、函数参数个数及重复声明。Rust 负责语言校验，具体版本的物理键名由 Mod 在接受提交前核实。

## 验收重点

- 新旧提交并行、递归、参数与事件变量同名遮蔽；旧处理块读取注册者的最新值，快照和副本独立。
- 无法整除、负数取整、大整数精度、`Wait(1)` 与非法零拍等待；动态参数解析到同一键而冲突时，整拍没有输入。
- 监听提前返回、暂停在函数赋值中途、取消所有者、旧块在新调用期间返回。区分显式 null 与字段缺省。
- 暂停两侧及 F8 续跑的日志归属、多提交输出、错误时保留已打印内容；实机核对停止帧和保留队列。
