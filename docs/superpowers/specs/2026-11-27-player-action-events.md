# 玩家动作事件与触发结果

本规格面向 Minecraft Java Edition 26.3 本地单人实例。脚本通过 `ON(事件名)` 等待动作结果，模型通过该次 `input_script` 的停止结果读取触发时的信息。语法沿用[事件与监听](../../input-script/events.md)。变量、事件参数和按结果筛选留待后续设计。

## 五种事件

| 事件 | 何时触发 | 返回的现场数据 |
| --- | --- | --- |
| `BlockBroken` | 内置服务器确认本地玩家的挖掘实际移除了目标方块。生存和创造模式都适用。挖掘取消、被拒绝、爆炸或邻居方块连带脱落均不算 | 维度、目标格坐标、破坏前的方块 ID |
| `LeftGround` | 客户端本地玩家一次模拟中由接地变为离地。主动跳起、从边缘走出都算，持续腾空只触发一次。重新接地后可再次触发 | 维度、观察到离地时玩家脚底的坐标 |
| `ScreenOpened` | 客户端实际进入一个新 Screen，包括从一个界面切换到另一个界面。覆盖背包、箱子、工作台、聊天、进度等。单纯关闭回到世界、同一实例重新布局、遮罩和右上角进度提示均不算 | 界面类型，沿用 `inspect_game` 的类型命名，如 `InventoryScreen` |
| `DamageBlocked` | 服务端结算本地玩家使用物品格挡的伤害量大于零。全挡和部分格挡都算，物品不限于盾牌。部分格挡后原版仍接受伤害时，同一击也可命中 `Hurt` | 格挡物品 ID、本次挡下的伤害点数 |
| `BlockInteracted` | 本地玩家对准方块使用，服务端最终受理这次交互。包括方块响应（开关门、开箱）和手中物品响应（锄地、去皮）。按一次受理的交互报告，原版在方块、空手回退和物品之间尝试多个分支时只记最终成功。单纯按键、放行到下一分支或被拒绝均不算 | 维度、点击的格坐标、使用的手和交互前的手中物品 ID（空手为 null）、该格前后两份方块状态 |

`LeftGround` 按玩家接地标志取边沿。正常上下台阶时若保持接地，即使 Y 改变也不触发。初次观察、重生、换世界时建立基线；在空中注册或恢复不会补发已发生的离地。暂停响应沿用最近的输入边界，画面中玩家可能已经开始下落。

`BlockInteracted` 的前后状态取自同一次服务端交互，记录方块 ID 和原版状态属性，保留布尔、数字的 JSON 类型。例如开门时 `before.open` 为 `false`、`after.open` 为 `true`。关门命中同一事件，两个值相反。开箱时前后方块状态可以相同，客户端真正进入容器界面时还可命中 `ScreenOpened`。在方块上放置物品时，返回的位置始终是点击的格；原版有可能修改相邻格。

## 工具返回和输入时序

当至少一个已注册且空闲的监听接受一次通知时，记录一条 `events`。规则同时适用于现有五种玩家事件。按客户端观察顺序记录，同一次通知有多个监听命中时合为一条；其 `listeners` 按注册顺序给出来源，复用已有的块号、行号及适用的调用栈。各处理块继续按现有输入边界和注册顺序派发。服务端事件以客户端接到确认的时刻判断监听资格。注册窗口结束以后到达的确认沿用现有监听生命周期。

每次成功提交打开一个观察窗口，包括本次续跑时仍有效的旧监听。工具返回最终停止帧时，把截至该帧的记录封存为 `events`。需要暂停的世界先经过已有的服务端同步标记，再在客户端停止帧渲染完成、开始可选的 PNG 读回之前封存。脚本中间的显式截图不封存记录。停止帧之后到达的通知仍按队列规则处理，图片编码耗时不延长本次观察窗口。

所有正常停止原因都返回这些记录，包括显式 `PAUSE`、快捷键和 `end`（含处理块自然结束产生的停止）。处理块执行 `RETURN` 时记录仍保留到该次工具调用返回。手动恢复期间没有待返回的调用时，下一次调用从新的观察窗口开始。`pause_listeners` 继续描述本次停止的直接监听来源；例如处理块只执行 `RETURN` 时，事件可以出现在 `events` 中而不成为暂停来源。

例如下面是一次开门记录的字段节选。模型能在函数返回后读到原先的门状态。

```json
{
  "event": "BlockInteracted",
  "dimension": "minecraft:overworld",
  "position": {"x": 12, "y": 64, "z": -3},
  "hand": "main_hand",
  "item": null,
  "before": {"id": "minecraft:oak_door", "open": false},
  "after": {"id": "minecraft:oak_door", "open": true},
  "listeners": [{"event": "BlockInteracted", "block": 1, "line": 2}]
}
```

建议每次调用返回最近 32 条记录，按从早到晚排列。超出时以 `events_omitted` 给出省略的早期记录数，省略反馈不会阻止脚本中监听执行。新版无命中时返回空数组。旧 Mod 缺少记录能力时，MCP 省略 `events`。事件名仍通过现有握手协商，提交旧 Mod 未支持的事件名时须在派发输入前报错。

## 验收

- 实际挖掉方块，并以中途松开作对照；主动跳起、走出边缘、持续下落和普通接地移动分别核对事件次数。
- 打开背包、箱子、进度界面；核对打开箱子时服务端交互结果与客户端实际打开界面的两个独立来源。
- 用盾牌全挡、部分格挡、空举盾和仅由金心吸收分别验证 `DamageBlocked` 和 `Hurt`；核对同边界监听的注册顺序。
- 实际打开和关闭同一扇门、锄地、去皮和空手点击无响应的方块，对照服务端状态、MCP 返回和截图。
- 通过 `Wait(n)` 限定监听窗口，分别验证提前暂停、函数提前返回和等待自然结束。覆盖同一次通知命中多个监听、处理块忙时的重复通知、旧监听在新调用中命中、跨暂停不重复报告、关闭截图和超出记录上限。
