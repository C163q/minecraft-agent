# 输入脚本的 IMPORT 设计

目标是让内联脚本和文件脚本复用已有的[函数](../../input-script/functions.md)。调用方仍写 `$name()`。以下为实现前规格。

## 导入与路径

`IMPORT "path"` 独占一行，位于当前源文件所有函数定义和入口块之前，可重复写多行。路径使用与 `ScreenShot` 相同的 JSON 双引号字符串语法，结束引号之后可跟行尾注释。导入在提交时处理，消耗零拍。

绝对路径直接使用。内联 `script` 中的相对导入从 Rust MCP 进程的工作目录解析，与现有的相对 `path` 参数一致。文件中的导入从声明所在文件的目录解析，嵌套导入逐层使用各自的目录。例如 `tasks/explore.mcinput` 导入 `../lib/walk.mcinput`，后者再导入 `common.mcinput`，最终读取的是 `lib/common.mcinput`。

## 名字与冲突

逐文件私有名字可以让各库使用同名辅助函数，但会使同一个调用名的含义取决于声明所在的文件。本轮选定**整次提交共用一张函数表**。收集入口文件及所有直接、间接导入文件中的定义，再解析调用，沿用现有的函数名大小写规则。只要两处定义同名，整次提交报错，即使函数从未被调用、定义内容完全一致，或其中一处位于入口文件。诊断列出函数名和两处定义的来源与行号，内联来源标为 `<inline>`。

在一次提交内按规范化后的文件路径去重。例如 `walk` 和 `mine` 同时导入 `common`，其中的 `$helper` 只登记一次。若 `walk` 和 `mine` 各自定义 `$helper`，则构成冲突。解析当前导入链时再次遇到链上的文件，按循环导入报错，并显示从入口到重复文件的链。各次工具提交分别建立名字表。

## 入口与提交边界

被导入文件可以只含导入和函数，也可以带一个顶层 `BEGIN … END`。直接提交的根脚本必须有一个入口。Rust MCP 读取并校验整套源文件，只有根入口参与执行。库文件自己的入口可作为直接运行时的演示或测试；导入它不会触发其中的按键、`CLEAR` 或其他游戏操作。

设计建议把库入口也纳入静态校验，包括语法、函数引用和键名。读取、解析、重名或校验失败时，游戏里的原队列和暂停状态保持原样。成功提交后，队列持有当次读到的函数定义；暂停时编辑库只影响后续提交。

验收覆盖内联与文件的相对路径、菱形导入去重、循环链、入口与库重名、两个库的未调用函数重名、导入带入口的文件，以及暂停期间修改库再提交。
