# input_script 的单次调用拍数上限

调用者可以用可选参数 `max_ticks` 限制一次 `input_script` 在交回控制前执行的输入拍数，默认值为 600。`script` 和 `path` 使用同一规则。显式传入的值必须为正整数，参数错误应在提交新块和恢复游戏前返回。

## 计数与暂停

Rust MCP 将上限传给 Fabric Mod，由 Mod 复用本次请求的 `ticks` 计数。这里选择在实际派发时计数，因为静态拆分脚本无法得知鼠标移动、事件处理及已保留队列共同占用多少拍。多块并行执行一拍只计一次。零拍控制、渲染、截图和等待服务端确认都不消耗额度。单人存档切换沿用原有的等待期限。

执行完第 `max_ticks` 拍时，先结算该拍的输入、已观察到的事件及拍末零拍指令。若已有返回原因，例如 `end`、`pause`、`hotkey` 或 `world_changed`，返回原结果。若原本还会派发下一拍，立即按普通 `PAUSE` 流程停止，返回 `pause_reason: "max_ticks"`。同一边界有脚本要求保存的截图时仍应写入文件。工具结果沿用本次的 `include_screenshot` 和事件记录。

按上限暂停后，剩余等待、函数与监听、按键及按钮保持状态、鼠标移动余量均按既有暂停规则保留。新提交按既有规则合并，每次调用从零计数。通过快捷键手动继续时，已完成调用的额度随该调用结束。

## 验收示例

| 脚本内容 | 上限 | 预期结果 |
| --- | --- | --- |
| `Wait(5)` 后接 `Key(w)` | 3 | 第 3 拍返回 `max_ticks`，保留两拍等待和按 W 的一拍 |
| `Wait(3)` 后接 `END` | 3 | 第 3 拍返回 `end` |
| `Wait(3) PAUSE` | 3 | 第 3 拍返回 `pause` |
| 空入口块 | 1 | 第 0 拍返回 `end` |
| `Wait(601)` | 省略 | 第 600 拍返回 `max_ticks`，保留一拍等待 |

实机还需核对上限处的服务端暂停确认和停止帧、取消返图、等待鼠标移动时中断再继续，以及上限与事件暂停、存档切换同拍时的返回原因。
