# 输入脚本的函数与提前返回

本规格面向 `input_script` 的解析器、游戏端队列与实机验证。目标是把一段有限时长的操作封装成函数，在观察到事件时提前交还给调用者。语法与时序沿用[脚本结构](../../input-script/timing.md)、[暂停与继续](../../input-script/pause.md)及[事件监听](../../input-script/events.md)。

## 定义与调用

本轮采用提交内定义。相对于会话级函数注册，同一份脚本文本足以确定调用目标，暂停续跑也有确定的版本。跨文件复用留待下一轮设计显式 `IMPORT`。

```text
FUNCTION $watch
BEGIN
    ON(Hurt)
    BEGIN
        RETURN
    END
    Wait(10)
END
BEGIN
    $watch()
    Key(s)
END
```

零个或多个函数定义写在唯一顶层入口之前。函数名区分大小写，采用 `$[A-Za-z_][A-Za-z0-9_]*`。首版为无参数、无返回值的调用。声明、调用与 `RETURN` 分别独占一行，可附行尾注释。定义和调用本身消耗零拍，执行从入口开始。解析时先收齐符号，支持前向引用、直接递归和间接递归。重复定义、未定义引用及未被调用函数中的非法输入也须在提交生效前报告源行。旧脚本沿用原有的语法和能力协商；向旧 Mod 提交使用新指令的程序时，在派发前报告版本不兼容。

## 调用、返回与监听

每次调用记录自己的函数、调用点、下一条指令以及本次调用注册的监听。调用者停在调用点，其他顶层块继续按拍叠加。函数体自然到达 `END` 或执行 `RETURN` 都在当前边界返回，上层的下一条输入可以在下一可派发拍生效。函数返回撤销所属调用及其子调用尚未派发的输入、等待、监听与尚未完成的处理块。已经按下的键和鼠标按钮、已经启动的鼠标移动沿用现有的保持与续跑规则。

外层监听在子调用期间继续生效。事件处理块里的 `RETURN` 退出注册该监听的那次调用。处理块调用辅助函数时，辅助函数自己的 `RETURN` 先回到处理块。属于同一个边界的处理块按实际注册顺序开始处理零拍控制，再合并尚未派发的输入；外层先返回时，同一边界尚未派发的内层动作随其调用一起撤销。显式 `PAUSE` 与处理块自然 `END` 保留原有的暂停语义。

处理块内直接嵌套 `ON` 仍属于语法错误；从处理块调用的函数可以声明自己的监听。已观察的处理块在注册者同一边界的返回之前执行首批零拍控制。若其中执行了 `PAUSE`，注册者当时待执行的 `RETURN` 或自然返回留到恢复，除非同一批处理块中另一次已经执行的返回直接撤销了注册者。

监听对函数最后一拍的拍末观察仍有资格，先处理该边界已观察到的事件，再自然退出函数。处理块在同一边界经任意零拍调用到达显式暂停时，保留尚在执行的调用现场；若有待未来输入拍才能执行的动作，函数自然退出时一并撤销。同一边界已经执行的暂停和截图请求仍生效，即使稍后另一个处理块返回并撤销其来源。所有脚本的顶层普通 `END` 均继续保留已触发的处理块，包括定义了函数的脚本。

顶层或其监听里的显式 `RETURN` 放弃该顶层调用所属的余下工作。它沿用所属顶层 `END` 的停止条件：当前 MCP 提交正常返回 `end`，其他新提交不会因旧顶层返回而停止。若先 `PAUSE` 再 `RETURN`，暂停时下一条仍是旧调用的 `RETURN`；新提交通过完整校验后，在恢复边界按原归属执行。同名新函数只属于新提交。新块开头的 `CLEAR` 优先移除旧工作，仅清监听的零拍提交保留旧执行位置。`CLEAR` 和 `RETURN` 各占一行。

## 深度与诊断

每条调用链最多同时有 **32 层函数调用**。入口深度为 0，调用第一层函数后为 1。`ON` 处理块承接注册者的调用深度；处理块调用辅助函数才加一层。并列的提交和处理块各算自己的链，顺序调用在返回后立即腾出一层。游戏端在进入第 33 层前报错，给出函数名、调用点源行和调用链。采用显式调用栈，按需进入函数，保留暂停处的位置；递归体在编译和查询时都不展开。

每份提交在相邻输入拍之间最多进入函数 **4096 次**，覆盖同层反复调用以及分支式零拍递归形成的大量工作。计数由该提交的执行分支共享，有输入拍实际推进才重置。两种上限均按运行时实际到达的路径判断。超限时停止继续派发，在当前边界移除出错提交的剩余工作并暂停；有正在等待结果的 MCP 调用时向其报告出错提交与源行。其余提交的队列以及此前已经产生的输入状态按暂停规则保留，允许查询、清理和继续。手动续跑期间发生的错误也须可由 `inspect_input` 查看。

## 查询与验证

`inspect_input` 的快照沿用顶层来源、源行与分页机制，区分同一函数的多次活动调用，能定位暂停处、下一条指令及监听的注册调用。仅列实际排队的工作，对未来函数调用列出调用点。函数表随提交保存；世界切换、取消及例外的死亡处理遵循原有队列清理边界，已清理的执行现场不可再恢复。跨维度重生若只留下本次死亡的处理块，该处理块及其内部辅助调用保留相应函数定义。对已清理注册者的 `RETURN` 结束该处理分支；若原提交仍在等待，则按原请求的段尾停止条件返回。不会复活旧世界的调用者，也不会以旧请求的段尾结束后来的提交。

验证覆盖第 32 和第 33 层、互递归、顺序调用、零拍预算、前向引用、错误提交的原子性，以及示例的超时与受伤两条路径。实机覆盖内外层同时命中、在处理块中调用辅助函数、暂停时提交同名函数、旧顶层与函数返回后新输入的合并，以及 MCP 的停止帧和队列快照。
