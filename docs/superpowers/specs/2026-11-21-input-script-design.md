# input_script 的时间与键盘输入

本草案采用方案 A，以客户端输入 tick（下称“一拍”）描述时间。范围为普通输入块内的等待、键盘状态及脚本来源。此前的实机探针验证过[逐拍输入](../../research/2026-11-21-keyboard-tick.md)与[跨暂停的鼠标余量](../../research/2026-11-21-buffered-mouse.md)，此处的文本语法尚待实现。

## 等待与行内组合

普通输入行消耗一拍，同一行的普通按键在这一拍共同生效。空行代表一拍空增量输入。第 1 列即以 `//` 开头的注释行跳过；只有缩进和注释的行消耗一拍。解析时需要保留原始行首空白。

建议将行首的 `Wait(n)` 展开为 n 拍空增量输入。行尾若还有普通输入，将它们放在展开后的下一拍。这样可以直接按下表数拍：

| 块内的一行 | 展开后的输入 | 总拍数 |
| --- | --- | ---: |
| `Wait(1)` | 空 | 1 |
| `Wait(5)` | 空、空、空、空、空 | 5 |
| `Wait(1) Key(w)` | 空；下一拍 W | 2 |
| `Wait(2) Key(w) Key(a)` | 空、空；下一拍 W 和 A 同时按住 | 3 |

空增量下，已启动的鼠标移动继续推进，显式按住的键继续保持，上一拍临时声明的键按下述规则更新。等待位于行中间、重复等待或 n 为零时的语法仍待讨论。

## 临时按住与显式按住

- `Key(w)` 要求 W 在本拍处于按下状态。相邻拍连续声明 W 时保持按住。在第一个省略 W 的输入 tick 开始时释放，除非显式按住仍然有效。
- `KeyPress(w)` 从本拍开始持续按住 W。`KeyRelease(w)` 从本拍开始解除显式按住。若前一拍由 `Key(w)` 保持、这一拍由 `KeyPress(w)` 接手，游戏持续看到 W 按下，交接时不产生额外的释放或按下事件。

例如，假定开始时 W 已松开：

```text
KeyPress(w)
Wait(5)
KeyRelease(w)
```

第 1 拍按下 W，第 2 至 6 拍保持，第 7 拍开始时释放。该片段占七拍，其中六拍按住 W。

下列两段在这两拍及结束时的 W 状态相同，都只产生一次按下事件：

```text
Key(w)
KeyPress(w)
```

```text
KeyPress(w)
Wait(1)
```

同一拍内对同一个键同时要求按下和释放的处理方式仍待确定。

## 脚本来源

`input_script` 支持直接传入脚本文本，也支持指定脚本文件路径。两种来源读取到的相同文本应展开为相同的输入序列，包括空行和缩进注释。建议参数分别命名为 `script`、`path`，每次调用二选一，由 Rust MCP 读取文件后交给同一解析入口。相对路径的解析基准仍待确定。
