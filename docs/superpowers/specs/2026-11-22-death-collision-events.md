# 玩家死亡与分轴碰撞事件

本规格为本地单人 Minecraft Java Edition 26.3 的 `ON` 增加三个事件来源。监听范围、同拍注册顺序、暂停、队列来源和处理中的重复触发沿用[输入事件规格](2026-11-22-input-events-design.md)。

## Death

客户端处理指向当前本地玩家的原版死亡通知时，产生一次 `Death`。原版 `ClientPacketListener.handlePlayerCombatKill` 在客户端线程识别玩家，随后显示死亡界面或请求立即重生。两条路径都应触发。成功消耗不死图腾保命时不触发。

事件取自死亡通知。脚本在最近的输入边界响应，截图仍遵循停止帧规则。立即重生时不保证停止帧显示死亡界面。

跨维度重生时，原调用可以完成死亡暂停并保留同一次通知触发的处理块。旧维度的普通队列、监听和保持状态清除。若另外一个工具调用正运行，换维度沿用原有的中断规则，避免其结果被归到较早的死亡通知。

## CollideX 和 CollideZ

两个事件分别使用世界坐标 X、Z。在原版 `Entity.move` 中，潜行防跌落等修正先调整请求位移，碰撞求解随后给出允许位移。沿用原版逐轴比较的容差。当某轴的位移因碰撞被截短，这一轴当拍就算受阻，包括玩家先向前移动一小段才碰到墙的情况。站立、沿另一轴直行、在空地松键停下均不会凭此触发。

每个客户端模拟拍分别记录两轴是否受阻。同一拍多次移动取该轴是否曾受阻。从未受阻进入受阻时产生一次事件。连续顶墙期间保持该轴的状态；暂停、查询、恢复或重新注册监听均不产生新的碰撞。经过一个实际模拟且该轴未受阻的拍，下一次碰撞才会再次触发。玩家重生或更换世界后重新跟踪。斜向擦墙只触发被挡的一轴，同时撞进墙角可在同一边界触发两轴。

## 实机验收

- 用本地玩家实际移动对照空地直行、斜向擦墙和墙角。核对 `input_script` 返回的事件名、声明行和两轴同时触发时的注册顺序。
- 在首次撞墙时暂停，保持同方向输入恢复；随后走开一拍或更久，再撞同一面墙。两次实际接触各触发一次。
- 分别在正常死亡界面和立即重生规则下造成致命伤害，再用不死图腾做对照。核对死亡通知、客户端画面与模型收到的停止结果。
