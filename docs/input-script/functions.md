# 函数、调用与返回

用 `FUNCTION $name` 定义无参数的函数，用 `$name()` 调用。`RETURN` 提前退出本次调用。下面的脚本最多等待十拍，在受伤时提前结束等待，然后按一拍 S。

```text
FUNCTION $wait_for_hurt
BEGIN
    ON(Hurt)
    BEGIN
        RETURN
    END
    Wait(10)
END

BEGIN
    $wait_for_hurt()
    Key(s)
END
```

如果在第 3 拍末观察到 `Hurt`，第 4 拍就按 S。如果十拍都没受伤，第 11 拍按 S。调用和返回均消耗零拍。

## 定义的范围

将所有函数定义写在本次脚本的入口 `BEGIN` 之前。函数名区分大小写，由英文字母、数字、下划线组成，首字符须为字母或下划线。定义、调用、`RETURN` 和各自的 `BEGIN`、`END` 都独占一行，可加行尾注释。函数可调用同一份脚本内定义在后面的函数，也可递归调用自己。

调用点能引用本次提交及其[导入文件](imports.md)中的定义。暂停时提交另一份含有同名函数的脚本，两份调用各用自己的版本。未定义的引用、重复定义以及未调用的函数内的非法指令都会导致整份提交被拒绝。

## 哪些输入会继续执行

| 返回位置 | 下一步 |
| --- | --- |
| 函数体内的 `RETURN` 或函数自然到达 `END` | 从调用者的下一条指令继续 |
| 函数的 `ON` 处理块内的 `RETURN` | 退出注册监听的那次函数调用，同时退出它尚在执行的子调用 |
| 处理块调用的辅助函数内的 `RETURN` | 回到该处理块的调用点之后 |
| 顶层入口或其 `ON` 内的 `RETURN` | 提前结束所属顶层块。若它是当前提交，按顶层 `END` 返回 |

函数退出时清除本次调用下未派发的输入、等待、监听与处理块。已经启动的鼠标移动保留余量，已按下的键和按钮仍遵循原来的临时保持或显式保持规则。外层监听在执行子调用时也生效。同一边界命中多条监听时按注册顺序处理。外层先返回，尚未派发的内层处理块也随之结束。

函数最后一拍仍可触发监听。处理块在该边界走到 `PAUSE` 时保留现场。如果函数自然结束，仍需在未来输入拍派发的处理动作随本次调用清除。处理块自然走到自己的 `END` 时沿用[事件暂停规则](events.md)。

`PAUSE` 后另起一行写 `RETURN`，恢复时才执行返回。此时若提交了新脚本，旧函数返回到旧调用者，双方下一拍的输入照常合并。旧顶层块的返回只结束该块。新脚本以 `CLEAR` 开头时，先清除旧工作。仅提交 `CLEAR_LISTENERS` 时，保留旧执行位置。详见[暂停与继续](pause.md)。

## 运行上限

入口深度为 0，每条调用链最多同时进入 32 层函数。监听处理块继承注册者深度，调用辅助函数时再加一层。在两次实际输入拍之间，同一份提交及其处理块合计最多进入函数 4096 次。已经返回的调用也计入这项预算。

尝试进入第 33 层或同一边界第 4097 次调用时，游戏停止派发并清除出错提交的剩余工作，其他提交的待执行输入和已经产生的按住状态保留。工具报告出错的块、调用链和源行。若由 F8 继续时遇到上限，使用 [inspect_input](inspect.md) 查看 `pause_reason` 和 `last_error`，据此决定继续还是清理输入。
