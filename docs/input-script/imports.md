# 从文件导入函数

把 `IMPORT "路径"` 写在脚本开头，每行一个，随后写函数定义和入口 `BEGIN … END`。路径是 JSON 双引号字符串，可以包含空格，右引号后可以写 `//` 注释。路径应指向 UTF-8 编码的普通文件，也可以是指向该文件的符号链接。

例如，将下面的函数保存在 `lib/walk.mcinput`：

```text
FUNCTION $step
BEGIN
    Key(w)
END
```

在 `tasks/explore.mcinput` 写：

```text
IMPORT "../lib/walk.mcinput"
BEGIN
    $step()
    Wait(1)
END
```

将 `tasks/explore.mcinput` 作为 `input_script` 的 `path` 提交，会按一拍 W，再等一拍。直接提交的脚本需要一个入口，供其他脚本导入的文件可以只放函数或其他导入。

## 路径从哪里算

| 写下 `IMPORT` 的位置 | 相对路径的起点 |
| --- | --- |
| 工具参数 `script` 中的内联文本 | MCP 进程的工作目录 |
| 用 `path` 提交的文件或被导入的文件 | 写下该行的文件所在目录 |

两种来源均可使用绝对路径。上例中的 `walk.mcinput` 如果再写 `IMPORT "common.mcinput"`，读到的是 `lib/common.mcinput`。通过符号链接导入时，嵌套路径从真实文件所在目录解析。Agent 在另一条 shell 命令里执行 `cd` 只影响那条 shell 命令。现有 `ScreenShot` 输出路径仍按[脚本结构与时间](timing.md)中的规则解析。

## 重名、入口与暂停

一次提交内，根脚本和所有直接或间接导入的文件共用函数名。两个文件分别定义 `$step`，即使未调用，也会报错并列出两个定义位置。多个库引用同一个规范化路径时，该文件只加载一次。文件相互循环导入时，错误会显示导入链。

库文件也可以带一个自己的顶层入口。直接提交这个文件时会执行它；导入时，入口里的语法、函数引用和键名仍会校验，游戏只执行根脚本的入口。这样可在库里保留可单独运行的演示。

每次提交重新读取导入文件。若游戏停在旧函数的 `PAUSE`，修改库后提交新脚本，旧调用继续用旧定义，新调用使用新定义。读取或校验失败会保留原来的暂停状态和待执行输入。函数返回与监听的例子见[函数、调用与返回](functions.md)。
