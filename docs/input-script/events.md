# 玩家事件与监听

在顶层块或函数内写 `ON(事件名)`，随后用一对独占行的 `BEGIN`、`END` 包住处理块。执行到声明时注册，注册占零拍。处理块内可以使用普通输入、等待、函数调用和控制指令。要在事件发生时提前退出注册者，见[函数与返回](functions.md)。下面的脚本在接下来的 40 拍监听受伤；一旦受伤，在最近的输入边界暂停并默认返回停止帧。

```text
BEGIN
    ON(Hurt)
    BEGIN
        PAUSE
    END
    Wait(40)
END
```

- `Hurt` 在客户端收到内置服务器对本地玩家的受伤确认时触发。微量伤害、金心吸收、部分格挡后的伤害和冷却期间接受的差额伤害都算。完全格挡或被原版拒绝的命中不会触发。
- `HpLost` 在客户端观察到普通生命值下降时触发。只掉金心、回血或同值重发都不会触发。首次同步建立基线。同一击可分别触发两种监听。
- `Death` 在客户端处理本地玩家的死亡通知时触发。普通死亡和立即重生都触发；不死图腾成功保命时不会触发。立即重生时停止帧可能显示加载或重生后的画面。若这次死亡使玩家跨维度重生，原调用仍可收到暂停结果；只有本次死亡触发的处理块可在新维度续跑。旧维度的普通输入、监听和按住状态会清除。独立提交的新调用沿用原有的换维度中断规则。
- `CollideX` 和 `CollideZ` 分别表示玩家沿世界 X 或 Z 轴的请求位移首次被碰撞截短。斜着擦墙时只触发被挡的一轴，撞进墙角时两轴可同拍触发。站立或在空地松键停下不会触发。

持续顶墙时，每轴只触发一次。暂停、恢复或重新注册监听都保留接触状态。该轴经过一个完整的未受阻模拟拍后，再次受阻才会重新触发。重生和更换世界会重置接触状态。

## 动作事件

| 名称 | 触发条件 | `events` 中的现场字段 |
| --- | --- | --- |
| `BlockBroken` | 服务端确认本地玩家挖掉目标格。生存和创造模式都适用，中途松开或爆炸破坏不算 | `dimension`、整数格坐标 `position`、原方块注册名 `id` |
| `LeftGround` | 本地玩家在模拟中从接地变为离地，包括跳起和走出边缘。连续腾空只触发一次 | `dimension`、当时的脚底坐标 `position` |
| `ScreenOpened` | 客户端进入一个新界面，例如背包、箱子、进度或聊天。关闭回到世界、重新布局和进度提示不触发 | `screen`，如 `InventoryScreen` |
| `DamageBlocked` | 服务端确认玩家使用的物品挡下正数伤害。全挡和部分格挡均触发。剩余伤害被接受时，同一击还可触发 `Hurt` | `item` 为格挡物品注册名，`blocked_damage` 为挡下的生命点数 |
| `BlockInteracted` | 服务端受理针对方块的使用动作，包括开关门、开箱、锄地和去皮。双手或多个交互分支的尝试以实际受理的动作为准 | `dimension`、被点击的 `position`、`hand`、交互前的 `item`（空手为 null）、该格的 `before` 和 `after` |

例如对准方块后运行以下脚本。按下左键后最多再等 40 拍。挖掉方块时函数提前返回，两条路径最终都会松开左键。调用方可以查看返回的 `events` 判断是否成功挖掉方块。

```text
FUNCTION $mine
BEGIN
    ON(BlockBroken)
    BEGIN
        RETURN
    END
    MousePress(left)
    Wait(40)
END
BEGIN
    $mine()
    MouseRelease(left)
END
```

开门和关门都命中 `BlockInteracted`。对照 `before.open` 和 `after.open` 即可判断方向。箱子可以受理点击而保持相同方块状态；例如箱盖被实心方块挡住时，原版仍可受理交互。要确认已进入容器，查看独立的 `ScreenOpened` 记录。服务端确认到达客户端时监听须仍然有效，因此一般应在点击前注册，点击后留出等待时间。

## 生效时序

监听持续到所属块最后一拍的拍末。暂停和追加新块会保留尚未结束的块及其监听。同一条声明的处理块尚未结束时，重复事件直接忽略。另行声明的监听独立响应。开始处理时，同一边界的新处理块按实际注册顺序叠加到尚未派发的输入上；键和鼠标按钮各取最后一条同名声明，移动按合速度叠加。已派发的输入不会撤回。

处理块的 `END` 暂停并保留其他块的待执行输入。若事件恰在当前提交的末拍拍末触发，处理块首行是 `PAUSE` 则当场返回 `pause`；首行是 `Key(s)` 或 `Key(s) PAUSE` 则先返回 `end`，S 留到恢复后才派发。三种情况下本次调用都只计到原块最后一拍。

`CLEAR_LISTENERS` 独占一行，消耗零拍，注销当时已注册的所有监听。已触发的处理块保留其剩余输入，随后注册的监听照常生效。普通 `CLEAR` 同时清除更早块的待执行输入与其监听。

## 停止结果

事件处理块执行显式 `PAUSE` 时，`pause_reason` 为 `pause`，`pause_listeners` 列出在该边界执行暂停的监听。每项的 `event` 是事件名，`block` 和 `line` 指向顶层块及其 `ON` 声明行。一次有多项时按注册顺序列出。查询现有监听和剩余输入见[查询当前输入状态](inspect.md)。

`events` 按观察顺序列出本次调用期间被监听接受的通知，截止到最终停止帧。关闭截图也会返回。一条通知只记一次，`listeners` 列出本次命中的全部声明及适用的调用栈。即使处理块只执行 `RETURN`，该事件仍会出现在结果中。续跑旧监听时，新的触发归入当前调用。保留最近 32 条，超出时 `events_omitted` 给出省略的早期条数。空数组表示本次没有命中；旧版 Mod 可省略整个字段。

例如 `events` 中的这一项表示盾牌挡下了 0.5 点伤害，命中的是第 3 行注册的监听。

```json
{"event":"DamageBlocked","item":"minecraft:shield","blocked_damage":0.5,"listeners":[{"event":"DamageBlocked","block":1,"line":3}]}
```
