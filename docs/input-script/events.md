# 玩家事件与监听

在顶层块内写 `ON(事件名)`，随后用一对独占行的 `BEGIN`、`END` 包住处理块。执行到声明时注册，注册占零拍。处理块内可以使用普通输入、等待和控制指令。下面的脚本在接下来的 40 拍监听受伤；一旦受伤，在最近的输入边界暂停并默认返回停止帧。

```text
BEGIN
    ON(Hurt)
    BEGIN
        PAUSE
    END
    Wait(40)
END
```

- `Hurt` 在客户端收到内置服务器对本地玩家的受伤确认时触发。微量伤害、金心吸收、部分格挡后的伤害和冷却期间接受的差额伤害都算。完全格挡或被原版拒绝的命中不会触发。
- `HpLost` 在客户端观察到普通生命值下降时触发。只掉金心、回血或同值重发都不会触发。首次同步建立基线。同一击可分别触发两种监听。
- `Death` 在客户端处理本地玩家的死亡通知时触发。普通死亡和立即重生都触发；不死图腾成功保命时不会触发。立即重生时停止帧可能显示加载或重生后的画面。若这次死亡使玩家跨维度重生，原调用仍可收到暂停结果；只有本次死亡触发的处理块可在新维度续跑。旧维度的普通输入、监听和按住状态会清除。独立提交的新调用沿用原有的换维度中断规则。
- `CollideX` 和 `CollideZ` 分别表示玩家沿世界 X 或 Z 轴的请求位移首次被碰撞截短。斜着擦墙时只触发被挡的一轴，撞进墙角时两轴可同拍触发。站立或在空地松键停下不会触发。

持续顶墙时，每轴只触发一次。暂停、恢复或重新注册监听都保留接触状态。该轴经过一个完整的未受阻模拟拍后，再次受阻才会重新触发。重生和更换世界会重置接触状态。

## 生效时序

监听持续到所属块最后一拍的拍末。暂停和追加新块会保留尚未结束的块及其监听。同一条声明的处理块尚未结束时，重复事件直接忽略。另行声明的监听独立响应。开始处理时，同一边界的新处理块按实际注册顺序叠加到尚未派发的输入上；键和鼠标按钮各取最后一条同名声明，移动按合速度叠加。已派发的输入不会撤回。

处理块的 `END` 暂停并保留其他块的待执行输入。若事件恰在当前提交的末拍拍末触发，处理块首行是 `PAUSE` 则当场返回 `pause`；首行是 `Key(s)` 或 `Key(s) PAUSE` 则先返回 `end`，S 留到恢复后才派发。三种情况下本次调用都只计到原块最后一拍。

`CLEAR_LISTENERS` 独占一行，消耗零拍，注销当时已注册的所有监听。已触发的处理块保留其剩余输入，随后注册的监听照常生效。普通 `CLEAR` 同时清除更早块的待执行输入与其监听。

## 停止结果

事件处理块执行显式 `PAUSE` 时，`pause_reason` 为 `pause`，`pause_listeners` 列出在该边界执行暂停的监听。每项的 `event` 是事件名，`block` 和 `line` 指向顶层块及其 `ON` 声明行。一次有多项时按注册顺序列出。查询现有监听和剩余输入见[查询当前输入状态](inspect.md)。
