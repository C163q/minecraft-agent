# 暂停与继续

`PAUSE` 可以独占一行，也可以放在输入行末尾。它消耗零个输入 tick。写成 `Key(s) PAUSE` 时，S 先在这一拍生效；世界随后暂停，工具返回停止帧。块开头的 `PAUSE` 可在第一拍前停止。`Wait(5) PAUSE` 会先走完五拍。输入没有执行到的部分保留在游戏端。

## 从下一拍合并

假设第一次提交：

```text
BEGIN
Key(a) Key(w)
Key(s) PAUSE
Key(d)
Key(q)
END
```

工具在第 2 拍返回，S 仍为 `temporary`。[查询队列](inspect.md)会列出 `Key(d)` 和 `Key(q)`。随后提交：

```text
BEGIN
Key(space)
Wait(1)
Key(b)
END
```

整个新块通过语法和键名校验后才恢复。`BEGIN` 本身占零拍。旧块的下一拍与新块的第一拍对齐：

| 恢复后的拍 | 旧块 | 新块 | 效果 |
| --- | --- | --- | --- |
| 1 | `Key(d)` | `Key(space)` | 松开 S，按住 D 和空格 |
| 2 | `Key(q)` | `Wait(1)` | 松开 D 和空格，按住 Q；旧块耗尽 |
| 3 | 已耗尽 | `Key(b)` | 松开 Q，按住 B；本次提交到达 END 并返回 |

新块的等待只占用本块的时间。每个块的 `WaitMouseMove()` 等待当前全部移动完成，其他块仍可逐拍发出输入。屏障在拍与拍之间检查，空闲时放行后才派发下一拍的新移动。旧块中显式出现的 `PAUSE` 会暂停所有块；新块较短时，它的 `END` 也会让旧块的余下部分等到下次恢复。

同一拍先合并指令，再派发键和鼠标按钮。多个块同时声明同一个键或按钮时，较新的块覆盖较旧的声明。例如旧块的 `Key(w)` 遇到新块的 `KeyRelease(w)`，这一拍只执行释放。省略该键或写 `Wait(1)` 都保留旧块的声明。同一块同一拍的按下与释放仍会报错。各块的鼠标移动继续按[合速度规则](mouse.md)同时生效。

`CLEAR` 独占一行。它消耗零拍，清除更早提交的块中尚未执行的输入，以及已经启动的鼠标移动余量，保留显式按住的键和按钮。要取消旧点击，可让新块从 `CLEAR` 开始。要一并松开 W，可在下一行写 `KeyRelease(w)`。

## 暂停快捷键

默认使用 **F8**，可在 Minecraft 的“控制 → 按键绑定 → 杂项 → 暂停 / 继续 Minecraft Agent”中修改。背包和箱子界面也能使用；在原版暂停菜单或设置界面，先回到游戏。玩家和脚本都能按当前绑定的键。切换发生在按下边沿；保持、键盘自动重复和松开都不会再次切换。`KeyPress(f8)` 触发暂停后仍为显式按住；新提交的 `BEGIN` 可以直接恢复，随后可用 `KeyRelease(f8)` 松开它。脚本的保持状态和玩家手动按键彼此独立。

- **运行中按下**：在输入拍边界暂停。如果有工具在执行脚本，工具会返回停止帧。当前未完成的等待只保留剩余拍数。
- **在中断处按下**：继续原脚本，直到下一个暂停点或本次提交的 `END`。
- **在 END 处按下**：世界持续运行，继续推进保留的输入和移动。没有新声明的临时键在下一拍松开，显式键继续保持。再次按下可暂停。
- **提交新块**：可以解除手动暂停，并从同一输入边界叠加新的指令。需要原地观察时使用 `inspect_input`。

原版菜单本身暂停世界时，返回的 `world` 为 `not_needed`。在菜单内执行的显式 `PAUSE` 会保留，关闭菜单后可用 F8 或新块继续。普通 `END` 若在原版菜单内返回，则关闭该菜单可恢复正常运行。

返回的 `ticks` 是本次工具调用实际走过的输入拍数。`pause_reason` 为 `pause`、`hotkey` 或 `end`，分别对应脚本暂停指令、快捷键和本次块的段尾。
