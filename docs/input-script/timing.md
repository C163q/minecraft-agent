# 脚本结构与时间

每一拍对应一个客户端输入 tick。下例从所有键已松开的状态开始。

## 完整示例

```text
BEGIN
Key(w)
Key(w) Key(space)
Wait(2) Key(a)
END
```

第 1 拍按住 W。第 2 拍继续保持 W，同时按下空格。第 3 拍松开两键，第 4 拍仍为空输入，第 5 拍按住 A。整块共 5 拍。`END` 本身消耗 0 拍；下一次推进输入时，由下一拍决定 A 是否继续保持。

## 输入行和注释

每次提交一个由 `BEGIN` 和 `END` 包围的块，两者分别独占一行，可附行尾注释。普通按键行占一拍，同一行中的键在这一拍共同生效。空行或只有空格的行在块内也占一拍。

从原始行的第 1 列开始写 `//`，整行消耗 0 拍。如果 `//` 前面只有缩进，则去掉注释后留下一个空输入 tick。下面的块恰好占两拍：第一拍按住 W，第二拍松开。

```text
BEGIN
// Skip this comment line.
Key(w) // Press W for this tick.
  // One empty input tick.
END
```

## 等待

| 写法 | 占用拍数及效果 |
| --- | --- |
| `Wait(n)` | 展开为 n 拍空增量输入。独占一行的 `Wait(1)` 总共只占 1 拍 |
| `Wait(n) Key(w) Key(a)` | 前 n 拍为空输入，在第 n+1 拍同时按住 W 和 A |

等待时长必须是正整数，写为十进制数字，范围为 1 至 18446744073709551615（`u64`）。`Wait(0)` 和 `Wait(-1)` 都是语法错误。当前只支持行首单个 `Wait`。解析器先检查整块，发现错误时返回源行号。

## 脚本来源

工具设计接受内联文本 `script` 或文件路径 `path`，每次选择一种。两种来源在 Rust 核心中共用同一解析器。脚本文件使用 UTF-8，保留空行和缩进，支持 LF 和 CRLF。使用文件时可传绝对路径；核心库将相对路径交给调用方指定的基准目录解析。正式 MCP 接入尚待实现。
