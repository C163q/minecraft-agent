# 脚本结构与时间

每一拍对应一个客户端输入 tick。下例从所有键已松开的状态开始。

## 完整示例

```text
BEGIN
Key(w)
Key(w) Key(space)
Wait(2) Key(a)
END
```

第 1 拍按住 W。第 2 拍继续保持 W，同时按下空格。第 3 拍松开两键，第 4 拍仍为空输入，第 5 拍按住 A。整块共 5 拍。`END` 本身消耗 0 拍；下一次推进输入时，由下一拍决定 A 是否继续保持。

## 输入行和注释

每次提交一个由 `BEGIN` 和 `END` 包围的块，两者分别独占一行，可附行尾注释。普通输入行占一拍，同一行中的按键和鼠标操作在这一拍共同生效。块内的空行和只有空白字符的行各占一拍。

跳过行首空白后，以 `//` 开头的整行注释消耗 0 拍。指令后面的行尾注释保留该指令原有的拍数。需要给一个空输入拍加注释时，可以显式写 `Wait(1)`。下例占两拍，第一拍按住 W，第二拍松开。

```text
BEGIN
    // Press W for one tick.
    Key(w)
    Wait(1) // Release the temporary hold.
END
```

## 等待

| 写法 | 占用拍数及效果 |
| --- | --- |
| `Wait(n)` | 展开为 n 拍空增量输入。独占一行的 `Wait(1)` 总共只占 1 拍 |
| `Wait(n) Key(w) Key(a)` | 前 n 拍为空输入，在第 n+1 拍同时按住 W 和 A |

等待时长必须是正整数，写为十进制数字，范围为 1 至 18446744073709551615（`u64`）。`Wait(0)` 和 `Wait(-1)` 都是语法错误。每行至多有一个行首等待。`WaitMouseMove()` 的实际等待时长由[进行中的鼠标移动](mouse.md)决定。解析器先检查整块，发现错误时返回源行号。

在拍末或两个输入拍之间暂停、恢复及合并多个块的规则见[暂停与继续](pause.md)。

## 脚本来源

工具接受内联文本 `script` 或文件路径 `path`，每次选择一种。两种来源在 Rust 核心中共用同一解析器。脚本文件使用 UTF-8，保留空行和缩进，支持 LF 和 CRLF。使用文件时可传绝对路径；MCP 从自身进程的工作目录解析相对路径。

## 停止时是否返回截图

工具参数 `include_screenshot` 是可选布尔值，默认为 `true`，适用于 `script` 和 `path`。例如，只查询这次执行的停止状态：

```json
{"script":"BEGIN\nWait(5) PAUSE\nEND","include_screenshot":false}
```

到达 `PAUSE`、`END` 或被暂停快捷键打断时，这次调用只返回文本状态，包含 `ticks`、`world` 和 `pause_reason`。停止确认、输入队列和恢复规则与默认模式相同。需要看图时，在下一次调用省略此参数或传 `true`，即可取得 PNG、原图尺寸和供 `cursor_hint` 使用的 `screenshot_id`。
