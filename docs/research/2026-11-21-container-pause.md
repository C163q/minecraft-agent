# Minecraft 26.3 单人世界与箱子界面暂停

2026-11-21 在 Linux 图形客户端验证。目标是在模型思考期间冻结单人世界，保留玩家正在操作的箱子界面，并能查询和恢复游戏。

## 环境与证据

HMCL 的 26.3 原版及 Fabric 实例均提供 SHA-1 为 `e877b6a07acd633fb3bb475002175cec036e7b87` 的客户端 JAR。游戏元数据声明 Java 25。使用 OpenJDK 27.0.1.1 的 `javac --release 25` 编译探针，产物 class 主版本号为 69。同一 JDK 成功启动 Fabric Loader 0.20.1，加载客户端探针及其 Mixin，进入独立测试世界并正常退出。探针直接使用本机游戏及启动器依赖编译；Gradle 和 Loom 构建链尚未验证。

## 原版暂停路径

26.3 的 `Minecraft.pauseGame(boolean)` 调用 `Gui.setPauseScreen(boolean, boolean)`。后者在已有活动 screen 时直接返回。无活动 screen 且运行未对局域网开放的内置服务器时，才会安装对应的 `PauseScreen`。箱子界面的原版对照与此调用路径吻合。

客户端在渲染后的更新阶段结合 `Gui.isPausing()`、内置服务器及局域网开放状态设置自身的暂停标志。内置服务器在自己的执行路径上读取 `Minecraft.isPaused()`。探针在有暂停请求时让 `Gui.isPausing()` 返回 true，解除请求时恢复原版判定。这个介入点保留了当前 screen，也保留了原版的单人游戏条件。由于客户端与服务器分别更新，发出请求和服务端确认暂停是两个可区分的时刻。

## 实机对照

探针从 HMCL 安装的库与资源启动独立客户端，以本地测试身份创建单人测试世界。服务端放置箱子、生成一头牛并为测试玩家打开箱子。客户端确认进入 `ContainerScreen` 后，记录该界面与玩家容器菜单的对象引用。以下世界时间和牛的已模拟 tick 数均在服务端线程读取。

| 操作 | 世界时间 | 牛的 tick 数 | 观测 |
| --- | --- | --- | --- |
| 打开箱子后调用原版 `pauseGame(true)`，间隔约 1.2 秒采样 | 22 → 47 | 1 → 26 | 服务端两次报告未暂停 |
| 启用探针暂停，等服务端确认后间隔 10 秒采样 | 47 → 47 | 26 → 26 | 服务端两次报告已暂停，客户端也报告已暂停，界面和容器菜单均为原对象 |
| 解除探针暂停 | 49 | 28 | 客户端与服务端均已恢复，箱子仍打开，模拟继续推进 |

在服务端确认暂停后，探针仍可向客户端和服务端线程提交只读任务并取得结果。这验证了实现暂停期间查询所需的游戏线程行为。模型经 Rust MCP 调用 `inspect_input`、脚本停止点与服务端 tick 的精确对应、截图时序，以及背包和聊天框各自的行为，均尚未经过端到端验证。

本次探针源码、构建和启动脚本保存在本机 `.tmp/probe/`，其中 `run-av3sa248/console.log` 的三个 `PROBE` 采样行对应上表。可在该目录运行 `python3 build.py`，再运行 `python3 launch.py` 复测；启动脚本使用独立的新目录，检查通过时打印 `PROBE PASS` 并以状态 0 退出。
