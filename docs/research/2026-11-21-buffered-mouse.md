# 未完成的鼠标移动跨暂停续跑与清除

2026-11-21 在 Minecraft Java Edition 26.3、Fabric Loader 0.20.1 的独立单人世界进行实测。确定性测试客户端通过 stdio 调用 Rust MCP 探针的 `input_script` 和 `inspect_input`，Fabric Mod 在游戏线程上维护剩余的相对鼠标位移。测试驱动传递逐拍记录，无需解析脚本文本。脚本语法与查询结果的公开格式均待讨论。

## 实验约定

水平向右为正，向左为负。目标总位移为 +120 个鼠标输入单位，每个输入 tick 最多移动 12 单位，游戏灵敏度固定为 0.50。启动移动的第一拍立即执行第一步；下一拍请求截图时，已有移动继续执行一步。到段尾采用已确认的 [END 返回条件](../development/README.md#end-的返回条件)。清除对照把清除请求放在新提交开头，在世界仍暂停时丢弃旧余量，然后执行新提交的第一拍。此约定用于区分操作顺序，清除在其他位置的语义仍待确定。

## 游戏与缓冲区对照

累计位移从起始朝向计算，单位为游戏鼠标输入单位。视角取自游戏实际处理相对输入后的玩家偏航角。

| 操作 | 该阶段实际输入 | 累计位移 | 段尾余量 | 偏航角 |
| --- | --- | ---: | ---: | ---: |
| 启动向右移动，下一拍截图，然后暂停 | +12、+12 | +24 | +96 | 3.6° |
| 暂停期间三次查询，间隔合计 10.05 秒 | 无 | +24 | +96 | 3.6° |
| 追加两拍空操作 | +12、+12 | +48 | +72 | 7.2° |
| 再追加六拍，使剩余移动自然完成 | 六次 +12 | +120 | 0 | 18.0° |
| 用相反输入回到初始朝向，再重建两拍暂停状态 | 十次 −12，再两次 +12 | +24 | +96 | 3.6° |
| 清除后提交向左 24 单位，仅给一拍 | −12 | +12 | −12 | 1.8° |
| 再给一拍，随后追加两拍空操作 | −12、0、0 | 0 | 0 | 约 0° |

第一次截图和 END 的返回图分别从游戏帧缓冲读回。两张图均对应已向右走完两步、仍剩八步的状态，青金石地标的屏幕横坐标中位数均为 755 px。追加两拍后该坐标为 710 px，继续向右转动得到图像验证。清除改向的首拍，地标从 755 px 回到 777 px，再一拍回到初始的 800 px。

三次暂停查询均返回客户端和服务端已暂停、世界时间 24、已执行两拍。测试还逐拍核对了全部 26 拍的位移符号、大小和实际转角，并逐字节比较工具返回的各张图片与游戏保存的 PNG。该实验覆盖单个进行中的水平移动，未验证重叠移动、事件中断或低帧率下同一渲染帧内存在多张中途截图的情况。

## 复核与语法讨论依据

本机 `.tmp/buffer/` 中保存探针和测试驱动。原始逐拍日志在 `trial/run-g_7hhmr8/console.log`，查询采样、等待时长与图像测量值在 `trial/checks.json`，原图在 `trial/ipc/`。在探针目录运行 `python3 launch.py 0.50 新目录名`，用另一终端执行 `python3 verify.py 新目录名` 可在新世界复测。

比较候选语法时，可以请读者仅看同一个例子就判断三件事：哪些操作消耗一拍，截图对应鼠标移动的第几步，新提交恢复前是否会先清除已有输入。这组对照提供可检查的预期结果。
